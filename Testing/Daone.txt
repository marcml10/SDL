Notice what happened?

With EP/BVA, we mostly asked: "Is this input valid?"

With Decision Tables, we asked: "What combination of conditions produces this result?"

With State Transition Testing, we're asking: "Given where the system currently is, what happens when this event occurs?"

=========== Concept : Error Guessing

========= Problem: Give me 5 things you would try because you suspect a developer might have made a mistake.

Email is required.
Password is required.
Password must be 8–20 characters.
Login button should be disabled until both fields contain something.
Valid credentials → login succeeds.
Invalid credentials → error message appears.

=== possible suspects: 

Email containing only spaces → developer checks empty but forgets whitespace.
Password containing only spaces → accepted because length is technically ≥8.
Copy/paste into password → accidentally blocked.
Leading/trailing spaces in email → system may handle them incorrectly.
Clicking Login twice quickly → two requests might be sent.
Correct credentials but button remains disabled → UI state isn't updated.
Invalid credentials → server returns an error but UI doesn't display it.
Login succeeds → browser back button might expose the login page incorrectly.
