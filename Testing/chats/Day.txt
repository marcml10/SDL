# Boundary Value Analysis

The requirement is:

> Password length must be **8–20 characters inclusive**.

So conceptually:

```text
         INVALID        VALID              INVALID
           ↓              ↓                   ↓
...  6   7 | 8   9 ... 18 19 | 20   21  22 ...
            ↑                  ↑
         minimum            maximum
```

The interesting points are around the boundaries:

```text
7   → just below minimum
8   → minimum
9   → just above minimum

19  → just below maximum
20  → maximum
21  → just above maximum
```

This technique is called:

> **Boundary Value Analysis (BVA)**

---

## Why do we care about boundaries?

Imagine a developer writes:

```javascript
if (password.length > 8 && password.length < 20) {
    // accept
}
```

The requirement was:

```text
8–20 inclusive
```

But the developer accidentally used:

```text
> 8
< 20
```

Now:

```text
8  → rejected ❌
9  → accepted
...
19 → accepted
20 → rejected ❌
```

The application would appear to work for most normal values.

For example:

```text
12 → accepted
15 → accepted
17 → accepted
```

A tester who only tests ordinary values might completely miss the bug.

But your boundary tests expose it immediately:

```text
8  → ❌
20 → ❌
```

That's why boundary testing is powerful.
