Ah, yes — I misunderstood you. You mean **conceptual videos for the Web fundamentals we identified for your SDET path**, not JavaScript videos.

For your goal, I’d structure the web-learning videos like this:

### 1. Start with: How the Web actually works

You want to understand this flow:

**Browser → DNS → server → HTTP request → server processing → HTTP response → browser**

[MDN — How the Web Works](https://developer.mozilla.org/en-US/docs/Learn_web_development/Getting_started/Web_standards/How_the_web_works?utm_source=chatgpt.com)

For video learning, **Hussein Nasser's “The Journey of an HTTP Request to the Backend”** is particularly relevant. It goes through DNS, TCP, the request, cookies, reverse proxies, API gateways, encryption, etc. ([Class Central][1])

**Watch this when we begin Web Fundamentals.**

---

### 2. HTTP — VERY important for you

Don't just memorize:

> GET = retrieve
> POST = create

I want you to eventually be able to look at this:

```text
POST /api/login HTTP/1.1
Host: example.com
Content-Type: application/json

{
  "username": "john",
  "password": "1234"
}
```

and understand **every part of it**.

Then understand the response:

```text
HTTP/1.1 200 OK
Content-Type: application/json

{
  "token": "abc123"
}
```

For a quick introduction, **HTTP Fundamentals in 10 Minutes** covers requests, responses, headers, cookies and cURL. ([Class Central][2])

There is also a more comprehensive Hussein Nasser HTTP collection covering HTTP versions, cookies, REST APIs, proxies, TLS, CORS, JWT, etc. ([Class Central][3])

---

### 3. Browser DevTools — extremely important for QA

This is one area where I want you to **learn by doing**, not just watching.

You need to become comfortable with:

* **Elements**
* **Console**
* **Network**
* **Application/Storage**
* **Sources**
* request headers
* response headers
* request payload
* response body
* cookies
* status codes
* query parameters

Chrome's Network panel lets you inspect request payloads, headers, responses and cookies directly. ([Chrome for Developers][4])

Microsoft also has short DevTools videos, including specifically **“Learn to Use the Network Tool.”** ([Microsoft Learn][5])

For an SDET, I'd actually make **DevTools practice one of your first exercises**.

---

### 4. Cookies → Sessions → Authentication

This is another major topic.

You should eventually understand:

```text
Login
  ↓
Server authenticates user
  ↓
Server creates session / token
  ↓
Browser stores credential
  ↓
Future requests carry credential
  ↓
Server identifies user
```

Then compare:

* Cookies
* Sessions
* localStorage
* sessionStorage
* JWT
* Authorization headers
* Bearer tokens
* refresh tokens
* HttpOnly
* Secure
* SameSite

A good video for this is **“Cookies, Sessions, JSON Web Tokens (JWT) and More”** from LearnWebCode, which covers cookies, CSRF, sessions, JWT and localStorage. ([Class Central][6])

MDN's current cookie documentation is also useful alongside the video. ([MDN Web Docs][7])

---

### 5. REST APIs

Then we'll learn:

```text
Client
   ↓
HTTP
   ↓
REST API
   ↓
Backend
   ↓
Database
```

You'll learn:

* API
* endpoint
* resource
* GET
* POST
* PUT
* PATCH
* DELETE
* request body
* query parameters
* path parameters
* headers
* authentication
* JSON
* status codes

This directly prepares you for **API testing** later.

---

### 6. CORS

After you understand HTTP and APIs:

```text
Frontend: https://app.example.com

          ↓ request

API: https://api.example.com
```

Then:

> Why did the browser block my request?

That's where **CORS** becomes important.

Don't study CORS before understanding HTTP/origins.

---

### 7. HTTPS / TLS

Only conceptually at first.

You should understand:

```text
HTTP
 ↓
TLS
 ↓
HTTPS
```

and what encryption/certificates are accomplishing.

You **do not** need to learn cryptography mathematically for your SDET goal.

---

### 8. URL / DNS

You'll learn:

```text
https://api.example.com:443/users?id=10#profile
│       │                │    │       │
│       │                │    │       └─ fragment
│       │                │    └──────── query
│       │                └───────────── path
│       └────────────────────────────── domain
└────────────────────────────────────── protocol
```

And:

```text
example.com
     ↓
DNS
     ↓
IP address
     ↓
server
```

MDN's web fundamentals material covers DNS, URLs, TCP/IP and HTTP at exactly the level we need initially. ([MDN Web Docs][8])
