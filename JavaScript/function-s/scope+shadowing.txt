## 1. What if `var` is inside a function inside a function?

Yes, the result **can change depending on where the `var` is declared**, because `var` belongs to the **nearest function scope**.

For example:

```js
function outer() {
    var x = 10;

    function inner() {
        var x = 20;
        console.log(x);
    }

    inner();
    console.log(x);
}

outer();
```

Output:

```text
20
10
```

There are **two different `x` bindings**:

```text
outer() scope
└── x = 10

    inner() scope
    └── x = 20
```

Why? `var x` in `inner()` belongs to `inner()`'s function scope. It doesn't overwrite `outer()`'s `x`.

### But this is different:

```js
function outer() {
    var x = 10;

    function inner() {
        x = 20;
    }

    inner();
    console.log(x);
}

outer();
```

Output:

```text
20
```

Because there is **no `var x` inside `inner()`**.

So JavaScript looks outward:

```text
inner scope
   ↓
Does inner have x? ❌
   ↓
outer scope
   ↓
x = 10 ✅
   ↓
change that x to 20
```

This is another very important distinction:

```js
var x = 20;  // create/use a local binding

x = 20;      // modify an existing binding found through lookup
```

# 3. `greet` vs `greet()` — you're close, but let's correct one phrase

You said:

> the first one return only the value of the function

Almost. The first one **doesn't return the value produced by the function**.

```js
function greet() {
    return "Hello";
}

const a = greet;
```

Here:

```text
a
↓
the function itself
```

You're storing a **reference to the function**.

You can later do:

```js
a();
```

and get:

```text
Hello
```

---

But:

```js
const b = greet();
```

actually **executes** `greet()` immediately.

The function returns:

```text
"Hello"
```

So:

```text
a → function
b → "Hello"
```

Think of it like this:

```text
greet
  ↓
"Here is the function itself"

greet()
  ↓
"Run the function"
  ↓
"Hello"
```

This distinction is **extremely important for QA automation**, because you'll constantly encounter things like:

```js
page.click
```

versus

```js
page.click()
```

and callbacks such as:

```js
button.onClick = handleClick;
```

versus:

```js
button.onClick = handleClick();
```

Those are fundamentally different ideas.
