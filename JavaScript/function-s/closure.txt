---connecting with CLOSURES
---------------------------------------------
function createCounter() {
    let count = 0;

    return function () {
        count++;
        console.log(count);
    };
}

const counter = createCounter();

---------------------------------------------
counter
   |
   ↓
inner function
   |
   ↓
lexical environment
   |
   ↓
count → 0

The count variable is still reachable.
Why?
Because the returned function still needs it.

So JavaScript says:
"I cannot remove this environment yet. Something can still access it." And the function won't work without the variable if 
it does not exist


"Any variables that are still needed by the inner function remain reachable."

-----------------------------------------

function outer() {

    let important = "keep me";
    let useless = "remove me";

    return function inner() {
        console.log(important);
    };
}

Closure environment

important → "keep me"

useless → can be removed

@Hoisting 

var x;
console.log(x);
x = 10;

x exists
↓
but has not yet received 10
↓
x → undefined


now using var x = 10; Now it exists does not throw an error 


console.log(x);
let x = 10;

It would throw "ReferenceError: Cannot access 'x' before initialization"

x → exists
    ↓
not initialized yet
    ↓
cannot be accessed

This period is called the Temporal Dead Zone (TDZ)


# The var case -------------------
binding exists
+
initial value is undefined

# The let case ------------------ (const has the same behavior as let )
binding exists
+
no usable value yet
+
access is forbidden 


let and const
│
├── bindings are created for their scope
├── cannot be accessed before initialization
└── have a Temporal Dead Zone
