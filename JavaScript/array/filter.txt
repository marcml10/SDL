# Now `filter()` — Deep

`map()` answers:

> **"What should each element become?"**

`filter()` answers:

> **"Which elements should stay?"**

Suppose:

```js id="h7p5nc"
const numbers = [1, 2, 3, 4, 5, 6];
```

We want only even numbers:

```text id="3vup1u"
[2, 4, 6]
```

We can write:

```js id="p9kq8m"
const result = numbers.filter(number => {
    return number % 2 === 0;
});
```

The callback is now making a **decision**.

For each element:

```text id="jv0t1u"
1 → 1 % 2 === 0 → false → ❌
2 → 2 % 2 === 0 → true  → ✅
3 → 3 % 2 === 0 → false → ❌
4 → 4 % 2 === 0 → true  → ✅
5 → 5 % 2 === 0 → false → ❌
6 → 6 % 2 === 0 → true  → ✅
```

Result:

```text id="8z5yqb"
[2, 4, 6]
```

### The crucial difference

`map()`:

```text
element → transform → new value
```

`filter()`:

```text
element → condition → keep/discard
```

Both return a **new array**.

---

## QA example

Imagine you have test results:

```js id="8a0ny4"
const results = [
    "passed",
    "failed",
    "passed",
    "failed"
];
```

You could get only failures:

```js id="d6z8ph"
const failures = results.filter(result => result === "failed");
```

Now:

```text id="0z9yie"
failures → ["failed", "failed"]
results   → ["passed", "failed", "passed", "failed"]
```

This kind of array manipulation is very common when processing API responses or test data.
