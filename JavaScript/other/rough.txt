# One particularly important distinction

Your current transcript has this excellent concept:

> JavaScript scope lookup searches for a **binding**, not a value that happens to be useful/non-undefined. 

I **do** want you to understand things at that level.

But I don't want you to then go:

> "If lexical environments are important, I should learn the ECMAScript specification's exact internal algorithms for lexical environment records."

No.

There's a difference between:

**deep conceptual understanding**

and

**deep implementation/specification knowledge.**

For you:

> **Conceptual depth = YES.**
> **Engine/specification depth = usually NO.**

That's going to be our rule.

# The same applies to `this`

I want you to understand `this` **very well**, because it will make classes, Page Objects and callbacks much easier.

You should be able to look at:

```javascript
const user = {
    name: "Alex",
    greet() {
        console.log(this.name);
    }
};

user.greet();
```

and explain exactly why `this` refers to `user`.

Then understand:

```javascript
const greet = user.greet;
greet();
```

and why the behavior changes.

And:

```javascript
const greet = user.greet.bind(user);
```

and why `bind()` changes it.

That's useful.

But you don't need to memorize every bizarre `this` edge case that can be constructed in JavaScript.

---

# Same thing with the event loop

**This one I want you to learn deeply.**

Because later you'll write:

```javascript
await page.click(...)
await page.locator(...)
await expect(...)
```

and if you don't understand asynchronous execution, flaky tests can seem like magic.

You should eventually be able to reason through:

```javascript
console.log("A");

setTimeout(() => console.log("B"), 0);

Promise.resolve().then(() => console.log("C"));

console.log("D");
```

and explain:

```text
A
D
C
B
```

—not just memorize the output.

That's directly useful.
